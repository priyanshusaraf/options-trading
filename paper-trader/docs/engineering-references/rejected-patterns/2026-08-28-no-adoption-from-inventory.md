# No infrastructure adoption from a source inventory

Decision: no runtime technology was adopted by the intake review.

The inspected research-job writers already compare the current owner and token in an authoritative database transaction. A new Redis lock or workflow engine would not be justified by the existence of a locking article. See the [source/code packet](../../research/kleppmann/source-notes/job-claim-fencing.md).

The same admission rule applies to Kafka, Kubernetes, microservices, CRDTs, custom ledgers, cryptographic protocols and low-latency frameworks. This is a rejection of adoption without evidence, not a permanent technical ban. Reconsider only for a reproduced correctness requirement or measured bottleneck, with exact source/licence review, operational consequences and tests.
