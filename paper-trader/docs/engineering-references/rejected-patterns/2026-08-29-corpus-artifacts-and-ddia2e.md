# Rejected patterns from the artifact and DDIA 2e packet

Date: 29 August 2026. These are bounded no-adoption decisions, not permanent
technology bans.

| Pattern | Why rejected now | Evidence required before reconsideration | Migration and rollback requirement | Release owner |
| --- | --- | --- | --- | --- |
| Kafka, CDC platform or event bus from the log papers | Strategy OS already has a plane-local transaction-bound outbox and polling authority. No throughput or cross-system failure requiring a new platform was reproduced. | A current dual-write or throughput failure, workload measurements, exact source/licence review and an operations owner. | Export/replay format, dual-run comparison, consumer cutover, rollback without lost/duplicated authority facts. | Exact affected V0/V1 subsystem and deployability owner. |
| Universal event sourcing/CQRS | The papers describe trade-offs and limitations. Current immutable facts do not require every table or workflow to become an event log. | A concrete recovery, audit or derived-state failure that cannot be closed with the current transaction/outbox model. | Preserve current source rows, mixed-version readers and a forward-repair path. | Exact domain owner. |
| Temporal, DBOS or Restate | DDIA 2e names durable workflows, but current crash/restart evidence is incomplete and no workflow-platform need was established. | Reproduced failure in the database-owned job state machine, capability comparison, dependency/licence review and staffed operations. | In-flight history migration without effect replay, durable export and tested return path. | Research-spine/robustness and deployability owners. |
| Redis or Redlock for job correctness | The inspected database sink already checks owner, run and exact token in its write predicate. The Redlock debate does not change that failure model. | A new external sink that cannot validate the database token, with a direct stale-writer counterexample. | No silent authority switch; reconcile old/new claims and prove rollback. | Exact side-effect owner. |
| CRDT collaboration in V0 | Local-first research does not prove semantic merge safety for executable trading graphs. Existing optimistic draft conflicts and immutable versions preserve the seam. | Product demand, graph-specific conflict semantics, counterexamples and revalidation proof. | Preserve every immutable version and conflict receipt; disable collaboration without rewriting graphs. | V2 collaboration owner. |
| Pre-emptive sharding | DDIA 2e includes multitenant sharding, but Stage A has no measured capacity claim. Tenant isolation and sharding are different decisions. | Per-tenant workload/SLO evidence showing current admission, quota or storage topology fails. | Online backfill, dual-read verification, restore, reshard and tested return path. | Measured-scale and deployability owners. |
| Microservices, Kubernetes or multi-region from DDIA scope | The public chapter titles frame trade-offs, not requirements. No team, deployment or availability evidence supports the operational cost. | Reproduced ownership/deployability bottleneck, NFRs, failure budget and staffed operations. | Explicit data/authority ownership, cutover, observability, failure containment and rollback. | Later scale owner. |
| Formal specification for routine features | DDIA 2e names formal and randomized testing, but the repository uses risk-weighted proof. | A critical money, authority, research-integrity or recovery state machine with a realistic counterexample hypothesis. | Model-to-code correspondence and normal integration/recovery tests remain mandatory. | Critical slice owner. |
| Treating the DDIA 2e table of contents as chapter evidence | The full book was unavailable. Section titles establish scope only. | A lawful copy or specific open primary source, read at exact locations. | Not applicable. | Professional-reference owner. |
| Pirated or access-control-bypassed book/material | The mandate permits only lawful material and honest inaccessible records. | A lawful owner-provided copy or public first-party source. | Not applicable. | Owner/legal source gate. |

No production dependency, deployable, database, queue, source of truth or runtime
was added or removed by this review.
