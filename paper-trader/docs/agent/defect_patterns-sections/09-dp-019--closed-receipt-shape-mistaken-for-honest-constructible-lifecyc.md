## DP-019 — Closed receipt shape mistaken for honest constructible lifecycle evidence

- Severity: Critical when a package supports migration, persistence, research
  integrity, deployability, phase acceptance, or any authority claim.
- Status: CONTAINED/BLOCKED. The first closed-JSON grammar owner package is
  frozen and root-rejected after an independent Sol Ultra review reproduced four
  material defects. Its single implementation repair is consumed. Product,
  test, PostgreSQL, migration, runtime, deployment, production, live, order, and
  money bytes remain unchanged. The actual JSON-only package owner never started.
- Incident: the grammar replaced executable package members with a finite
  100-member JSON, JSONL, and Markdown package and two external files. Owner
  tests passed 49 scenarios, and root independently reconstructed a package,
  relocation, race control, 24 negative controls, and three hash-binding
  controls. Fresh independent review then proved that the candidate case and
  mutation IDs differed from the accepted lifecycle oracle, historical receipts
  collapsed exact required diagnostic sets, and execution receipts omitted the
  required environment fact. The only validator required the final seal on
  every run, so it could not validate the required pre-seal state. Its receipt
  schema rejected the honest eight-item invocation while accepting ungrounded
  claims about nonexistent interpreters and package roots. It also accepted a
  fully resealed duplicate run ID across logs despite declaring global run-ID
  uniqueness.
- Root cause: the architecture closed package paths and object keys but did not
  bind the complete semantic universe to the accepted root lifecycle authority.
  It treated stage receipts as descriptions instead of executable predecessor
  states, treated shape-valid observations as proof of actual execution, and
  implemented uniqueness for event IDs without implementing the separately
  declared run-ID invariant.
- Violated invariant: a closed evidence grammar must bind every case, mutation,
  historical diagnostic set, relocation, and execution fact to independently
  accepted authority before candidate construction. Every lifecycle transition
  must execute from its exact predecessor without consuming its own or a future
  output. Execution evidence must record the complete real command and a
  sanitized exact environment fact set and must bind to external execution
  output. Every declared global identity constraint must be enforced across the
  complete package, not only within a selected field or file family.
- Why prior evidence missed it: the owner and root fixtures copied the candidate
  taxonomy and candidate four-item argv, so their passing controls proved the
  candidate was self-consistent. Root compared topology and mutation behavior
  but did not compare the candidate's finite IDs and historical diagnostic sets
  to the accepted lifecycle oracle before review. Both matrices tested duplicate
  event IDs and duplicate receipt run IDs but omitted one run ID reused across
  separate log files. The final-only happy path hid the absence of a pre-seal
  validator mode.
- False assumption: removing executable package members and closing every JSON
  schema makes all retained receipts authoritative and the declared lifecycle
  constructible.
- Permanent regressions: (1) require exact equality between candidate and
  accepted root case and mutation IDs; (2) retain every exact historical
  diagnostic set rather than one summary label; (3) require execution receipts
  to contain the actual full argv, executable, interpreter, cwd, execution root,
  sanitized environment fact set, return code, stdout hash, and stderr hash;
  (4) reject a nonexistent interpreter or execution root unless direct external
  evidence proves that observation; (5) execute each stage validator against
  only its exact predecessor package and reject any self or future dependency;
  (6) validate the pre-seal state without a final receipt or final seal, then
  validate the sealed successor separately; (7) reuse one run ID across two log
  files, fully reseal, and require rejection; (8) independently re-execute every
  package claim before root acceptance; and (9) retain the known passing
  relocation, hardlink, symlink, seal, race, and exact-restoration controls.
- Adversarial generalization: search evidence, migration, research, provider,
  tenancy, deployment, recovery, and money boundaries for schemas that validate
  claims without proving their producer ran; for final validators presented as
  stage validators; for candidate-selected taxonomies replacing accepted
  authority; and for local uniqueness checks presented as global identity.
- Transitive evidence map: accepted lifecycle authority -> root-frozen staged
  grammar -> honest external execution receipts -> stage-specific validation ->
  sealed JSON-only package -> PostgreSQL and migration evidence -> foundation
  closure -> Phase 5 and Phase 6 handoff. Every downstream claim remains blocked.
- Owner: a fresh staged-lifecycle grammar architecture capsule must replace the
  rejected grammar. Root must freeze the exact accepted authority projection
  before dispatch. One fresh owner may implement the external validators only
  from that projection, and one independent reviewer must add a new control.
