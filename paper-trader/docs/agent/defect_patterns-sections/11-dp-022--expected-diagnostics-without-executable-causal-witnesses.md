## DP-022 — Expected diagnostics without executable causal witnesses

- Severity: Critical when operation receipts support migration, research
  integrity, recovery, deployability, phase acceptance, or authority.
- Status: CONTAINED/BLOCKED. Root rejected the first unified semantic-stage
  executor authority after its initial validation and sole repair appeared to
  pass. The owner was interrupted before any required output or source was
  written; one read-only accepted-transform audit log remains. No reviewer or
  actual package started, and product, test, PostgreSQL, migration, runtime,
  deployment, production, live, order, and money bytes remain unchanged.
- Incident: the frozen `illegal_full_reseal` mechanic changed only the
  nonsemantic presentation owner to a 65-character string. The accepted
  transform therefore rejected on `presentation_owner`, while the separate
  lifecycle array required `GRAPH_COUNT_MISMATCH`. No graph count changed. The
  same authority represented all eight historical replays as only a recovery
  number plus the expected diagnostic array, with no immutable counterexample,
  transform, first guard, digest scope, or restoration target. It also described
  `multi_parent_loss` as one isolated edge removal even though the accepted
  driver's list comprehension replaces every non-first fixture with a duplicate
  of the first fixture.
- Root cause: root froze operation names, prose descriptions, dispositions, and
  expected arrays but did not freeze a causal witness for every observation. Its
  validator compared IDs and dispositions to accepted bytes and expected codes
  to lifecycle bytes as separate equalities. It never proved that each exact
  mechanic reaches the named generic predicate and diagnostic without reading
  expected authority.
- Violated invariant: every observed disposition and diagnostic must arise from
  an exact immutable input, one exact operation, and a general material predicate
  whose result changes when the mechanic changes. An operation ID, expected
  array, or historical role cannot supply its own observation.
- Why prior evidence missed it: the fourteen root self-tests mutated registry
  shape, hashes, source count, receipt fields, argv, and orchestration authority.
  None retained an operation ID and expected array while changing its mechanic.
  The validator checked accepted driver dispositions but did not compare the
  accepted predicate or complete AST behavior to the lifecycle diagnostic.
- False assumption: separately freezing a mechanic and an expected diagnostic
  makes the diagnostic causally observable, even when the mechanic changes no
  fact named by that diagnostic.
- Prevention invariant: freeze a complete causal witness row before dispatch:
  operation ID, immutable preimage, exact transform, mutated-state digest,
  general predicate ID and definition, expected first predicate, diagnostic,
  restoration target, and post-restoration positive check. The executor may
  contain general predicates but no case-ID or expected-array result lookup.
  Historical replays require exact independently authored counterexample inputs,
  not rejection labels. Root must independently execute each witness and reject
  mechanic drift with IDs and expected arrays unchanged.
- Permanent regressions: (1) change the `illegal_full_reseal` mechanic while
  retaining its ID and expected diagnostic and require rejection; (2) require
  its actual mutated fact to reach the named first predicate; (3) omit the input,
  transform, predicate, digest scope, or restoration rule from any of the eight
  historical operations and reject before execution; (4) reproduce the accepted
  `multi_parent_loss` AST behavior and reject an isolated-mechanic claim; (5)
  delete or alias one general predicate and require an affected witness to fail;
  (6) add a case-ID-to-result or recovery-ID-to-result lookup and reject its
  source; (7) rerun canonical, reverse, shuffled, and repeated schedules from
  fresh immutable copies; and (8) retain the existing label-only, copied-array,

## DP-023 — Constructed positive state and schema-shaped literals mistaken for consumed observations

- Severity: Critical when evidence supports lifecycle, migration, research
  integrity, recovery, deployability, phase acceptance, or authority.
- Status: CONTAINED/BLOCKED. The first causal-witness owner package is frozen
  and root-rejected after its initial attempt and sole repair. Root reproduced
  three direct false accepts before a broad rerun. No reviewer or actual package
  started. Product, tests, PostgreSQL, migration, runtime, deployment,
  production, live, order, and money bytes remain unchanged.
- Incident: `validate-stage` never read its package root. It constructed a
  positive stage object from the requested stage ID and accepted a hostile
  `CASES_COMPLETE` package containing an executable member, missing predecessor
  evidence, incomplete output, self and future dependencies, and no completed
  receipt. The source guard prohibited result lookup by scanning only dictionary
  keys, so `if operation_id == baseline: return ACCEPT` passed. Both source files
  also recorded filesystem encoding as a literal; a copied executor changed it
  to `forged-encoding`, passed source grammar, and emitted the fabricated value
  in an accepted observation.
- Root cause: external inputs, information-flow policy, and execution facts were
  represented by locally constructed or shape-valid values. The stage label was
  treated as authority to mint predecessor state; one known syntax represented
  the complete ID-to-result class; and an exact environment key set was treated
  as proof that each value came from the running process.
- Violated invariant: lifecycle evidence must consume and hash exact external
  predecessor bytes. A forbidden information flow must be closed across every
  syntax and indirection, not a selected AST node. Execution facts must come
  from named runtime APIs and be independently challenged against the process or
  operating system where feasible.
- Why prior evidence missed it: all six positive stage tests exercised the same
  constructor, and the future-dependency control mutated the constructor's
  object rather than a hostile package. The lookup control used a dictionary
  keyed by an operation ID, exactly the only syntax the guard inspected. The
  environment control compared the same literal between observation and receipt
  and checked keys, not the running interpreter's fact.
- False assumption: a deterministic positive-state constructor proves a stage
  is constructible, one forbidden spelling proves an information-flow class is
  closed, and a schema-valid literal proves observation.
- Prevention invariant: freeze an external content-addressed package state for
  every stage. The executor must enumerate, hash, and consume its complete
  current member set and receipts. Freeze a bounded source architecture in which
  ID use is confined to one mechanic-selector output type; a root taint checker
  must reject comparisons, match, containers, aliases, calls, returns, closures,
  hashes, and indirect result flows outside it. Environment facts must invoke
  named runtime APIs such as `sys.getfilesystemencoding()` and root must mutate
  each producer or compare against an independent current observation.
- Permanent regressions: (1) pass a hostile external stage package with missing,
  stale, future, self-dependent, executable, and incomplete members and require
  exact first diagnostics; (2) delete a predecessor member after the stage
  descriptor is read and require changed-after-read rejection; (3) attempt
  operation/recovery-ID result lookup through compare, match, list/tuple index,
  concatenation, hashing, alias, helper return, closure, partial, and container
  forms; (4) change each environment producer while retaining schema and require
  independent mismatch; (5) add an undeclared package member outside the single
  data file and require recursive snapshot rejection; (6) make any control
  return the wrong result and require root recomputation itself to reject; and
  (7) retain all DP-018 through DP-022 controls.
- Adversarial generalization: search migration preflights, deployment readiness,
