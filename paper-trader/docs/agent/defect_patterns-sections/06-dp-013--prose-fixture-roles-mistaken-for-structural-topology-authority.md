## DP-013 — Prose fixture roles mistaken for structural topology authority

- Severity: Critical when fixture topology supports migration, persistence,
  research-integrity, authority, deployability, or review acceptance.
- Status: CONTAINED/BLOCKED. The exhausted authority-partition capsule stopped
  before replay, PostgreSQL, or successor creation. Root independently accepted
  that blocked result. A fresh database-free constructibility recovery,
  correction evidence, transitive revalidation, and independent review remain
  open.
- Incident: the independent trigger-fixture consumer first rejected a table
  projection because PostgreSQL source-native `SERIAL` had been reduced to an
  `INTEGER`-shaped declaration. The sole bounded repair parsed `SERIAL`, but the
  same constructibility path then rejected `topology.target`. It searched for a
  row whose prose purpose equalled `trigger_target`, while the accepted fixture
  contract uses qualified descriptions such as
  `trigger_target_distinct_from_link_parent`. The label described why a row
  existed; it did not provide a stable identity, role, or relational proof.
- Root cause: source-native schema facts, stable row identities, typed row
  roles, and candidate-relative topology predicates were compressed into
  convenient strings. The consumer then interpreted those strings as an exact
  executable ontology. A label change could therefore break valid structure,
  while a structurally invalid graph could retain a familiar label.
- Violated invariant: executable fixture topology must derive from stable row
  identities, declared source-native schema facts, and explicit predicates over
  candidate rows and edges. Human-readable purpose text may annotate those
  facts but cannot select a row, prove a foreign-key relation, establish
  distinctness, or determine insertion and cleanup order.
- Why prior evidence missed it: the producer and consumer shared the same
  purpose vocabulary, and earlier checks exercised selected rows or aggregate
  counts rather than the complete typed role and predicate universe. The first
  independent source reconstruction exposed one projection mismatch; repairing
  it merely advanced execution to the next hidden string-based assumption.
- False assumption: a deterministic descriptive label is a stable structural
  key, and exact string equality proves the topology that the label names.
- Prevention invariant: freeze source-native schema facts or an independently
  verified normalization; assign every fixture row a stable identity; bind each
  identity to typed roles; express topology as named candidate-relative
  predicates; and maintain an explicit compatibility map from optional prose
  labels to roles and predicates. Consumers must accept a label rename that
  preserves structure and reject structural drift that preserves the label.
- Searched surfaces and current result: the blocked recovery enumerated eight
  immutable-trigger fixtures and 1,733 leaves across six authority classes. It
  derived 8,665 one-at-a-time map cases and seven semantic transforms, but
  executed none after the constructibility failure. The initial prototype and
  sole repair are exhausted. No successor exists, PostgreSQL never opened, and
  no product, test, migration, runtime, or deployability byte is accepted by
  this record.
- Permanent regressions: (1) reconstruct source-native column facts and prove
  the declared normalization, including `SERIAL`; (2) validate all eight
  fixtures through stable row IDs, full primary/foreign-key edges, insertion
  order, and reverse cleanup order; (3) rename every prose purpose while
  preserving roles and predicates and require acceptance; (4) preserve a
  familiar label while changing one identity, relation, distinctness rule, or
  ordering edge and require named rejection; (5) run the baseline and all seven
  transform outcomes; (6) remove one role, predicate, compatibility binding, or
  fixture and require package rejection; and (7) reject
  `REJECT_SELECTED_SUBSET_FALSE_GREEN_COMPLETE_AFTER_CHECKING_4_OF_24`.
- Adversarial generalization: search for display names, slugs, comments, labels,
  human descriptions, enum spellings, generated constraint names, or fixture
  aliases used as executable identity or relationship evidence. Apply the same
  rename-preserves-structure and structure-drifts-under-stable-label pair to
  migrations, tenancy, ownership, provider routing, graph identity, order
  attribution, and evidence registries.
- Transitive evidence map: source-native schema and fixture topology authority
  -> trigger-fixture correction evidence -> semantic package and complete
  PostgreSQL evidence -> native-state and migration evidence -> runtime and

  Critical review -> Phase 1-4 acceptance -> combined Phase 5/6 planning.

## DP-014 — Predicate-family presence mistaken for per-fixture witness authority

- Severity: Critical when a predicate result supports migration, persistence,
  research integrity, tenancy, authority, deployability, or review acceptance.
- Status: CONTAINED/BLOCKED. The exhausted constructibility owner stopped before
  any transform, successor, PostgreSQL invocation, or product change. Root
  independently reproduced and accepted the same-byte blocked result. A fresh
  database-free predicate-cardinality recovery, correction evidence, transitive
  revalidation, and independent review remain open.
- Incident: the consumer required a `DISTINCTNESS` result for every fixture
  because that predicate family existed in the global registry. The
  `research_dataset_manifests/immutable/v1` fixture contained one row. Its
  same-set domain of pairs with different stable row IDs was empty, so the
  consumer rejected `predicates.fixture_coverage`. Accepted inputs did not say
  whether this fixture should omit the predicate, record an explicit empty
  domain, or reject because a non-empty witness was mandatory.
- Root cause: the model collapsed four different facts into one registry entry:
  predicate-family availability, per-fixture applicability, the finite operand
  domain, and the obligation's empty-domain policy. It then treated family
  presence as proof that every fixture had at least one witness.
- Violated invariant: every predicate obligation must freeze its typed operand
  slots, independently derived applicability rule, finite candidate-relative
  tuple domain, cardinality policy, empty-domain policy, relation semantics, and
  named consumer branch before evaluation. Registry membership proves none of
  those subject-specific facts.
- Why prior evidence missed it: earlier work closed predicate names and typed
  topology but did not execute explicit zero, one, two, and three-plus domain
  boundaries. Aggregate counts and selected examples could remain green while a
  singleton fixture had no legal pair and no declared outcome.
- False assumption: if a predicate family is declared globally, it applies to
  every subject and every subject supplies at least one valid witness.
- Prevention invariant: use a closed predicate signature and an explicit
  applicability record for each fixture. `REQUIRED_NONEMPTY` rejects an empty
  domain as `MISSING_REQUIRED_DOMAIN`; `VACUOUS_ALLOWED` records `EMPTY_DOMAIN`
  and never an ordinary witness PASS; `CONDITIONAL` records `NOT_APPLICABLE`
  only when a separately declared antecedent is false. Named left/right
  singleton roles form one tuple; same-set distinct pairs with fewer than two
  members form an explicit empty domain.
- Searched surfaces and current result: the blocked owner reached one independent
  baseline consumer after its sole repair, then stopped at the singleton
  cardinality gate. The baseline rejected, zero of seven transforms ran, no
  successor exists, PostgreSQL never opened, and no product, test, migration,
  runtime, deployability, or Phase 1-4 claim is accepted.
- Permanent regressions: (1) independently derive applicability and exact tuple
  domains for all eight fixtures; (2) exercise zero, one, two, and at least
  three domain members; (3) prove named-role singleton distinctness rejects
  equal identities and accepts distinct identities; (4) prove same-set pair
  domains obey their declared empty policy without fabricated witnesses;
  (5) reject ordinary PASS, silent omission, or invented `NOT_APPLICABLE` for an
  empty domain; (6) accept label-only renames and canonical presentation reorder
  when structure is unchanged; (7) reject identity, role, edge, applicability,
  domain, or predicate drift under stable labels; (8) prove unrelated
  out-of-domain rows cannot change the result; (9) execute the baseline and all
  seven inherited transforms with changed-state and exact-restoration receipts;
  and (10) reject
  `REJECT_SELECTED_SUBSET_FALSE_GREEN_COMPLETE_AFTER_CHECKING_4_OF_24`.
- Adversarial generalization: search for every place where declaration of a
  family is treated as subject-level applicability or instance existence. This
  includes permissions, obligations, graph edge kinds, risk rules, capability
  sets, node conformance, provider parity, strategy/deployment authority splits,
  preflight checks, dynamic derivatives, runtime state, subscriptions, QoS,
  resource plans, recovery rules, admission, provider negotiation,
  multi-instrument joins, and cache-causality claims.
- Transitive evidence map: predicate signature and cardinality authority ->
  trigger-fixture correction evidence -> semantic package and complete
  PostgreSQL evidence -> native-state and migration evidence -> runtime and
  integration evidence -> numeric correction -> transitive revalidation -> one
  Critical review -> Phase 1-4 acceptance -> combined Phase 5/6 planning.
- Proportionality: require exact coverage of materially distinct applicability,
  domain, cardinality, and outcome classes. A verified equivalence partition may
  replace redundant permutations, but it must independently enumerate every
  concrete subject and reject omissions. Historical counts remain comparison
  evidence and cannot define the fresh universe.
