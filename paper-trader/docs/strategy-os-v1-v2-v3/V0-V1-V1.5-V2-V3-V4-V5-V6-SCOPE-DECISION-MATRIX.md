# V0–V6 scope matrix

Updated 6 September 2026: documentation consolidation of the accepted 29 August direction. This is the single working release matrix. It preserves feature ownership; it does not assert implementation or grant execution/deployment authority.

## Current V0 boundary

The [working plan](../agent/WORKING-PLAN.md) prioritizes the provider-driven OHLCV research, evidence and alerts journey, including cross-instrument inputs. CSV is optional. Broad options history, order flow, dynamic discovery and all-30-strategy coverage are deferred. Current implementation evidence belongs in [status](../agent/STATUS.md), not this matrix.

## Releases

| Version | Outcome |
| --- | --- |
| V0 | Research, evidence, monitoring and alerts, with account/commercial foundations. |
| V1 | Controlled execution, sizing, admission and operational trust. |
| V1.5 | Dynamic discovery and certified bounded single-leg derivatives. |
| V2 | Active portfolio and hedge intelligence. |
| V3 | Strategy assets and a distinct managed-allocation product; demand-led AI/ML. |
| V4 | Certified multi-leg campaigns and institutional/fund infrastructure. |
| V5/V6 | Corporate treasury and enterprise market risk. |

V1.1 is retired. V0.1 owns no separate capability bucket. Labels are provisional and maturity-gated; V5/V6 remain grouped in the accepted source rather than inventing a new split.

## Advancement gates

A later feature needs demonstrated demand, technical correctness, operational ownership, security, viable costs, provider/data rights and applicable legal readiness. Registered-user counts alone do not justify release or infrastructure adoption.

Keep public real-money execution closed in V0. Payment test mode is distinct from live charges. Managed capital, funds and enterprise treasury require their specific legal/commercial decisions. No roadmap row authorizes credentials, orders, money, deployment or outside-capital activity.
