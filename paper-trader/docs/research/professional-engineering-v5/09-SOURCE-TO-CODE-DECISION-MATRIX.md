# Source-to-code decision matrix

This matrix records the research step without turning a source principle into implementation authority. Repository evidence and release scope decide the response.

| ID | Source claim and exact location | Source model | Actual repository evidence | Failure hypothesis | Decision |
|---|---|---|---|---|---|

No hash-library adoption. |
| D-02 | Immutable facts and derived views should not be maintained by race-prone dual writes, `KLEPPMANN_LOGS_2015_V5`, **The problem with dual writes**, `logs-10` and `logs-13`. | Multiple representations of one fact. | Transaction-bound plane outboxes exist; WebSocket projection reloads durable state. | A UI/cache becomes authority after missed event. | Retain outbox/reload design. ## Rejected or deferred technologies

| Technology/pattern | Decision | Evidence needed to reopen |
|---|---|---|
| Kafka/event broker | REJECT now | Measured database-outbox throughput/recovery failure that bounded polling cannot meet. |
| Redis | REJECT now | A hot-state latency requirement plus durable rebuild contract and loss/flush test. |
| Celery/workflow engine | REJECT now | A durable orchestration requirement the current database claim/item state machine cannot express safely. |
| Distributed consensus service | NOT APPLICABLE at current scale | A multi-writer authority predicate that PostgreSQL transactions/advisory locks cannot protect. |
| Isabelle/HOL or other proof assistant | DEFER | A small critical state machine whose property tests/model checker cannot cover the named invariant. |
| New database/cache abstraction | REJECT | Prior-art, licence, migration, deployability and rollback evidence after a direct failing need. |
