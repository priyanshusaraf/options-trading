# Strategy OS V1 subphase contract matrix

Date: 24 August 2026

This matrix closes the execution detail below the revised phase descriptions. Every row inherits its phase's full objective, user problem, invariants, frontend/backend split, tenancy/security/provider/resource posture, risk policy, benchmark eligibility, rollout/rollback rules and model policy from `REVISED-V1-PROGRESS-MAPPER-2026-08-24.md`. The row states the exact delta and is normative.

## Machine linkage and capsule generation rule

- A named non-dynamic machine stage uses its existing capsule.
- A dynamic architecture stage must replace its following dynamic placeholders with exact capsules before any implementation stage becomes `ready`.
- When several rows map to one machine stage, the architecture capsule must generate one capsule per row or one explicitly combined capsule whose write paths are disjoint from all other work and whose acceptance contains every mapped row. A broad placeholder is never executable.
- Generated capsules inherit the row's dependency, write scope, migration/deployment classification, realistic failure hypotheses, direct tests, rollout/rollback, exit artifact and route. No row may be silently omitted or deferred without an exact new owner stage.
- Programme phases remain serial. `Parallel` below means disjoint children inside the current stage only.

Column key: `Change` includes contract/schema/API plus backend/frontend delta. `Risk/evidence` includes migration, tenancy/security, provider/data/resource, failure hypotheses, tests and benchmark. `Delivery` includes rollout, rollback, exit artifacts, route, parallelism and write ownership.
