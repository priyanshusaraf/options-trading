# Strategy OS product rules

The backend on port 8090 and React/Vite frontend on port 5173 expose one product. Hidden platform machinery must support the trader's graph, research, deployment, and operating workflow without becoming a second product model.

## Reject before accepting

- A test proves only its asserted contract. For a safety guard, show that a deliberate reversible violation makes the guard's own test fail.
- A causal-admission receipt is necessary, never sufficient, for deployment or live authority. It does not prove market truth, numeric validity, provider capability, resource fit, protection compatibility, or production readiness.
- Unknown or stale identity, ownership, provenance, causal metadata, provider capability, or authority fails closed. Existing risk reduction remains available.
- Do not infer deployment, migration head, database contents, test count, or runtime mode from prose. Query the owning tool or runtime and preserve the exact evidence path.
- Do not build a second IR, signal engine, component library, provider identity, deployment authority, or research ledger for convenience.

## Slice discipline

The active capsule defines allowed paths, nonclaims, owner gates, assignments, and verification. Work outside that interface requires a new capsule or an explicit owner decision. The untracked IR-v2 planning documents are future findings and remain excluded from Phase 3 closure.

Use proportional gates:

- Focused tests while implementing a local contract.
- The affected subsystem suite at the slice gate.
- Full backend and research suites once at a phase or release gate.

Use `.codex/scripts/make_review_package.py` only after the integrated diff and evidence logs exist. A critical reviewer returns separate SPEC and QUALITY verdicts. One recheck by that reviewer is allowed; a second rejection stops the slice for replanning.

## Product boundaries

- Graph versions and admitted artifacts are immutable and content addressed. Results bind to the versions that produced them.
- Research approval is admission consumed at activation, not a renewable authority lease. New authority needs an exact content match; withdrawal removes the signals that authority authored.
- Signals use completed candles. Backtest and execution must share admitted semantics. Same-bar fill claims are rejected where next-bar execution is required.
- Runtime configuration rows may intentionally override code defaults. Never clear an owner-set value without the owner naming that key.
- Provider symbols and tokens stay at adapters. Canonical instrument identity belongs to Strategy OS, and observation instruments may differ from execution targets.
- All promised P&L, equity, and backtest figures include the full configured charge stack.

For phase design use `architecting-strategy-os-phases`. For a nontrivial implementation use `executing-strategy-os-slices`. For a critical final diff use `reviewing-strategy-os-critical-changes`. For local browser/runtime evidence use `running-strategy-os-safely`.
